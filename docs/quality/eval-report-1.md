# Product-разбор baseline: «где врём»

**Статус:** фактический eval-отчёт пока не сформирован. На 2026-10-27 в репозитории нет baseline-модели, golden dataset и результатов eval-прогона. Примеры ниже — рубрика сортировки будущих ошибок по ущербу для студента, а не обнаруженные ошибки.

## Рубрика продуктовой приоритизации

| Тип ошибки | Пример для классификации | Ущерб пользователю | Приоритет для AI Engineer |
| --- | --- | --- | --- |
| Неподтверждённый факт | Ответ содержит утверждение, которого нет в источнике | Студент учит неверное; критический риск | P0: не допускать карточку к подтверждению без видимой ссылки на источник |
| Искажение условия/формулы | Потерян знак, единица, условие применимости или причинная связь | Может привести к неверному пониманию и ответу на зачёте | P0: блокировать публикацию при критическом искажении |
| Пропуск ключевого факта | Вопрос покрывает только часть определённого ответа | Создаёт ложное ощущение полноты | P1: проверять полноту по ключевым фактам и примерам курса |
| Двусмысленный или слишком широкий вопрос | Нельзя понять, какой ответ ожидается | Студент не может честно проверить себя | P1: разбивать на атомарные вопросы или отклонять |
| Дубликат | Несколько карточек проверяют одно и то же | Тратится время, важные темы остаются без покрытия | P2: объединять или показывать дубликат до подтверждения |
| Ложное отклонение ответа своими словами | Смысл верен, но формулировка отличается от эталона | Снижает доверие и мотивацию повторять | P1: сравнивать факты по рубрике, не строки текста |
| Нежелательный стиль | Ответ длинный, но точный и подтверждённый | Низкий ущерб, если смысл понятен | P3: улучшать после ошибок корректности и полноты |

## Какие ошибки терпимы

Стилистическая шероховатость и повтор темы терпимы только как черновик, который студент видит до подтверждения. Неподтверждённое утверждение, искажение формулы/условия и неверное засчитывание ответа нельзя считать терпимыми ошибками активной карточки.

## Что нужно заполнить после eval-прогона

Для каждого фактического примера добавить ID golden dataset, версию модели и промпта, входной фрагмент, ожидаемый и фактический результат, тип ошибки, частоту, тяжесть и Product-решение. Частоту не выводить из одного примера; приоритеты выше заданы по потенциальному ущербу, не по измеренной частоте.
