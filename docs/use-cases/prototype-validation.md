# Валидация use cases на прототипе

**Дата проверки репозитория:** 2026-10-27  
**Статус:** сквозной прогон заблокирован; живого прототипа в ветке нет.

Проверка состава `HEAD` нашла только README и документы в `docs/`. Исполняемых `frontend/`, `backend/`, `ml/`, миграций БД, compose-файла и публичного URL прототипа нет. Поэтому ниже зафиксирован план приёмочного прогона и блокеры, а не вымышленные результаты тестирования.

## Матрица прогонов

| UC | Сквозной путь, который нужно пройти | Статус | Необходимое доказательство |
| --- | --- | --- | --- |
| UC-01 Создать проверяемую колоду | Загрузить реальный конспект → получить черновики → открыть источники → принять, исправить и удалить карточки → убедиться, что колода сохранена | BLOCKED: нет прототипа | Запись прогона, тестовый файл без личных данных, ID сохранённой колоды, перечень принятых/изменённых/удалённых карточек |
| UC-02 Пройти сессию повторения | Открыть очередь → ответить без подсказки → сравнить факты → пропустить карточку → завершить и возобновить сессию | BLOCKED: нет UI, API и хранилища | Запись E2E-прогона, ID сессии, сохранённые статусы `answered`/`skipped`, следующая дата |
| UC-03 Отклонить недостоверную карточку | Найти неподтверждённый факт → выбрать причину → исправить/удалить → проверить, что карточка не попала в активную колоду | BLOCKED: нет генерации и активной колоды | Карточка и исходный фрагмент, причина решения, состояние колоды до/после |
| UC-01 → UC-02 E2E | Создать колоду и в той же сессии начать повторение одной принятой карточки | BLOCKED: отсутствует весь исполняемый контур | Один ID колоды, связанный ID сессии и запись полного пути |

## Разрывы и задачи

| ID | Разрыв | Владелец | Критерий закрытия |
| --- | --- | --- | --- |
| L3-P-01 | Нет единого развернутого прототипа для сквозного пути | Delivery | Публичный или локально воспроизводимый URL; одна команда запуска; UI проходит через API к модели и БД |
| L3-P-02 | Нельзя проверить происхождение и подтверждение карточек в интерфейсе | AI Engineer + Delivery | Черновик содержит ссылку на фрагмент; принятие/правка/удаление сохраняется и отражается в колоде |
| L3-P-03 | Нельзя проверить очередь, статусы ответа и восстановление сессии | Delivery | Сессия сохраняется; `answered` и `skipped` различимы после перезагрузки |
| L3-P-04 | Нет живых ошибок baseline для продуктовой приоритизации | Quality & Safety + AI Engineer | Eval-прогон даёт примеры, типы ошибок, метрики и версии данных/модели |
| L3-P-05 | Нет usability-прогона человеком вне команды | Product / VO | Человек проходит UC-01–03 без подсказок; наблюдения, неожиданности и разрывы записаны |

## Форма записи неожиданности

Для каждого фактического прогона записать: UC и версию прототипа; входные данные; ожидаемый и наблюдаемый путь; место остановки; точные слова/действия тестирующего; что удивило; серьёзность для пользователя; задачу, владельца и критерий повторной проверки. До реального прогона поле «что удивило» остаётся незаполненным.
