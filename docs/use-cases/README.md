# Use cases: лабораторная 2

**Статус:** проектные сценарии Product / VO. Сценарии нужно разыграть с человеком вне команды; такого прогона пока не было, поэтому поле проверки отмечено явно.

## UC-01. Создать проверяемую колоду

**Актёр:** студент первого курса, готовящийся к зачёту.  
**Цель:** получить небольшой набор карточек из собственного конспекта и понять, откуда взят каждый ответ.  
**Контекст:** до зачёта осталось от одной до двух недель; у студента есть текстовый конспект или PDF объёмом до 10 страниц.

### Основной сценарий

1. Студент выбирает «Новая колода» и загружает конспект.
2. Система принимает файл, показывает его название и начинает обработку.
3. Система предлагает до 30 черновых карточек: вопрос, ключевые факты, ответ и фрагмент источника.
4. Студент открывает карточку и сверяет ответ с исходным фрагментом.
5. Студент оставляет корректные карточки, исправляет формулировку или удаляет карточку.
6. Система сохраняет только подтверждённые студентом карточки и показывает число готовых карточек.

### Результат

Создана колода с карточками, у каждой есть источник; студент может начать первую сессию. События `deck_created`, `card_accepted`, `card_edited` и `card_deleted` можно посчитать.

### Альтернативы и ошибки

- Файл не поддерживается или пуст: система объясняет ошибку и не создаёт пустую колоду.
- В конспекте есть инструкция вроде «игнорируй предыдущие правила»: она считается текстом источника, не командой системе; карточка может ссылаться на этот фрагмент, но не должна менять правила обработки.
- Факт карточки не подтверждается источником: студент удаляет её или исправляет вручную; такая карточка не попадает в подтверждённую колоду.

**Проверка проживаемости:** не проведена. Наблюдаемый критерий: человек вне команды проходит шаги 1–6 без пояснений команды и может назвать, почему карточка принята, исправлена или удалена.

## UC-02. Пройти сессию повторения

**Актёр:** студент с готовой колодой.  
**Цель:** вспомнить материал без конспекта и записать результат следующего повторения.  
**Контекст:** у колоды есть карточки, назначенные на текущую дату; студент может отвечать свободным текстом.

### Основной сценарий

1. Студент открывает очередь повторения и выбирает колоду.
2. Система показывает вопрос без ответа и исходного фрагмента.
3. Студент пишет ответ своими словами и отправляет его.
4. Система показывает эталонные ключевые факты и источник; студент отмечает, какие факты вспомнил.
5. Система сохраняет результат карточки и показывает следующую карточку.
6. После последней карточки система сохраняет завершённую сессию и назначает следующий интервал.

### Результат

Есть завершённая сессия с количеством карточек, ответов и засчитанных ключевых фактов; колода появляется в очереди на следующую дату.

### Альтернативы и ошибки

- Студент пропускает карточку: система сохраняет статус `skipped`, не считает факт вспомненным и оставляет карточку для следующего интервала.
- Ответ отличается от эталона, но содержит ключевой факт: студент может засчитать факт по рубрике; буквальное совпадение не требуется.
- Сессия прервана: уже сохранённые результаты не теряются, а незавершённые карточки возвращаются в очередь.

**Проверка проживаемости:** не проведена. Наблюдаемый критерий: человек вне команды может пройти две карточки и объяснить, чем отличаются `answered`, `skipped` и завершённая сессия.

## UC-03. Отклонить недостоверную карточку

**Актёр:** студент-рецензент колоды.  
**Цель:** не допустить в повторение карточку, которая не следует из конспекта или проверяет несущественный фрагмент.  
**Контекст:** система уже показала карточку, эталонные факты и ссылку на источник.

### Основной сценарий

1. Рецензент открывает исходный фрагмент рядом с вопросом и ответом.
2. Сверяет каждый ключевой факт с фрагментом.
3. Выбирает причину: «нет в источнике», «искажает смысл», «дубликат» или «неясный вопрос».
4. Удаляет карточку либо исправляет её текст.
5. Система сохраняет причину решения и не включает отклонённую карточку в активную колоду.

### Результат

Недостоверная карточка не участвует в повторении, а причина решения доступна для оценки качества набора.

**Проверка проживаемости:** не проведена. Наблюдаемый критерий: человек вне команды находит источник, выбирает причину и получает колоду без отклонённой карточки.

## Общие правила сценариев

- Источник показывается до подтверждения карточки и после ответа в сессии.
- Студент принимает решение о карточке; модель не может сама сделать её обязательной для повторения.
- Недоверенный текст конспекта не меняет системные инструкции и права доступа.
- Каждый сценарий заканчивается событием, которое можно проверить в журнале или интерфейсе.

Диаграмма актёров и границ сценариев находится в [use-cases.puml](use-cases.puml).
